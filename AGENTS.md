# SystemKeeper — правила для ИИ-агентов

Сервис бекапов и мониторинга (см. README.md). Laravel 13, PHP 8.5, MySQL 8.4, очереди `database`, API-only (`/api/v1`).

## Коммиты

- Сообщения коммитов пишутся **на русском языке**: краткий заголовок в повелительном наклонении («Добавь…», «Исправь…»), при необходимости — описание после пустой строки.
- ИИ **не указывается** автором или соавтором: никаких строк `Co-Authored-By: Claude …`, `Co-authored-by: Copilot …`, «Generated with Claude Code» и подобных — ни в коммитах, ни в описаниях PR.
- Автор коммита — пользователь из `git config`; не меняй его.

## Локальная разработка (Docker)

Сервисы `compose.yaml`: `app` (php-fpm 8.5), `nginx` (порт `APP_PORT`, по умолчанию 8080), `mysql`, `queue` (`queue:work`), `scheduler` (`schedule:work`).

```sh
cp .env.example .env
UID=$(id -u) GID=$(id -g) docker compose up -d --build
docker compose exec app composer install
docker compose exec app php artisan key:generate
docker compose exec app php artisan migrate
```

Все команды PHP/Composer/Artisan выполняй через `docker compose exec app …`.

## Тесты

```sh
docker compose exec app php artisan test
```

Тесты используют отдельную БД `systemkeeper_testing` (создаётся при инициализации MySQL, `docker/mysql/init`). Каждое изменение сопровождай тестами; перед коммитом тесты должны проходить.

## Код

- Следуй соглашениям Laravel и стилю окружающего кода; форматирование — `docker compose exec app ./vendor/bin/pint`.
- API — только JSON под `/api/v1`; web-маршруты не развиваем.
- Секреты (SSH-ключи, токены Яндекс.Диска) не коммитятся и не пишутся в логи.

## Задачи в трекере «Просто задачи»

Проект SystemKeeper (id `536`) в «Просто задачах». API: `https://tasks.prosto.uno/api/v1`, токен — коннектор DevPilot (`Authorization: Bearer $(cat /srv/devpilot/storage/app/connectors/1/api_key)`); токен не выводить и не сохранять в проекте.

Разделы: Бэклог `516`, К выполнению `519`, В работе `517`, Ревью / тест `520`, Блокер `521`, Готово `518`.

Каждый чат, работающий над задачей трекера, обязан:

1. **Двигать задачу по разделам** по ходу работы: в начале — «В работе», когда код готов и тесты зелёные — «Ревью / тест», при остановке из-за внешней причины — «Блокер» (с комментарием почему), по завершении и проверке — «Готово». Перемещение: `POST /tasks/{id}/move {"section_id": N, "position": 0}`.
2. **Самостоятельно засекать время** — не таймером трекера. **Самая первая команда работы** — `date +%s > /tmp/sk-task-<id>.start`. По завершении посчитай минуты по этому файлу (`$(( ($(date +%s) - $(cat /tmp/sk-task-<id>.start)) / 60 ))`, минимум 1) и спиши **ровно замер**. Списывать «по ощущениям», округлять в большую сторону или подгонять — запрещено; если замер потерян, так и напиши в комментарии и ничего не выдумывай. Списание: `POST /tasks/{id}/time {"minutes": N, "spent_on": "YYYY-MM-DD", "note": "…"}` (не более 1440 минут на запись).
3. **Писать результат работы в задачу** комментарием (`POST /tasks/{id}/comments {"body": "…"}`, Markdown): что сделано, хеш коммита, ключевые файлы, контракт API (если есть), как проверено, что не сделано или осталось.
