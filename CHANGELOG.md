# Что нового в SystemKeeper

Формат: раздел на версию, заголовок `## vX.Y.Z — ГГГГ-ММ-ДД`. Раздел версии попадает в описание релиза на GitHub
и в окно «Что нового» в приложении.

## v0.1.10 — 2026-10-19

### Новое
- **Мониторинг доступности (аптайм).** Мониторы HTTP(S) (код ответа, слово на странице, заголовки, редиректы, срок сертификата), TCP-порта, ping и DNS-записи. Проверки по расписанию каждую минуту выбирают подошедшие мониторы; недоступным монитор становится после заданного числа неудач подряд, при сбое открывается инцидент, при восстановлении закрывается. Uptime за 24 часа, 7 и 30 дней, среднее время ответа, разовая проверка без сохранения и проверка «сейчас». История проверок хранится 30 дней.

## v0.1.9 — 2026-10-15

### Новое
- **«Найти автоматически», что бекапить на сервере.** SystemKeeper осматривает сервер по SSH (только чтение): настройки (`/etc`, cron, свои скрипты), сайты и приложения (`/var/www`, `/srv`, `/opt`, `/home`, `/root`), корни сайтов из nginx и Apache, каталоги docker compose проектов, тома Docker, почту и сертификаты Let’s Encrypt — с размерами. Предлагает исключения (`node_modules`, кеши, журналы, файлы СУБД) и показывает работающие базы MySQL/MariaDB, PostgreSQL, ClickHouse, MongoDB и Redis — на сервере и в контейнерах, — отмечая, какие ещё не добавлены для бекапа дампом.

## v0.1.8 — 2026-10-15

### Улучшения
- «Последние бекапы»: размер всех хранящихся бекапов и размер последних — в общих виджетах, у каждой группы, проекта и объекта.

### Исправления
- «Последние бекапы»: база данных, чей сервер в другом проекте, больше не считается дважды.

## v0.1.7 — 2026-10-15

### Новое
- **Страница «Последние бекапы»**: последний бекап каждого сервера и базы данных (нет бекапов — «НЕТ»), сгруппированные по группам проектов, проектам и серверам. Группы сворачиваются, состояние запоминается. Сверху — сколько всего, успешно, с ошибкой и без бекапов; у неудачных — ошибка и время последнего удачного.

## v0.1.6 — 2026-10-15

### Улучшения
- **Яндекс Диск: все файлы — по ссылке.** Раньше файлы меньше 8 МБ загружались напрямую — медленно (~0,3–0,5 МБ/с) и по одному, и бекап из множества мелких дампов шёл дольше многогигабайтного архива. Теперь Диск скачивает по ссылке всё, большие файлы — первыми.
- **Журнал синхронизации хранилища**: по каждому файлу — способ загрузки, размер, время и скорость. Те же строки — в журнале бекапа.

## v0.1.5 — 2026-10-15

### Новое
- **Бекап по ссылке-хуку.** У сервера и базы данных можно включить секретную ссылку: `POST` на неё запускает бекап — удобно вызывать из CI/CD перед деплоем. По ответу можно следить за ходом бекапа.
- **Что нового в приложении.** Нажмите на версию в меню — откроется история изменений по версиям; новые, ещё не установленные, отмечены.
- **Проверка обновлений вручную** — кнопкой в том же окне, не дожидаясь проверки раз в 10 минут.
- **Ход обновления по этапам**: ожидание бекапов, дамп базы, скачивание, перезапуск, проверка — с пояснением каждого шага; итог прошлого обновления (успех, ошибка, откат) виден в окне версии.

## v0.1.4 — 2026-10-15

### Новое
- **Яндекс Диск** как хранилище бекапов. Файлы от 8 МБ Диск скачивает сам по временной ссылке с SystemKeeper — это в разы быстрее загрузки напрямую. Число одновременных загрузок настраивается в подключении (1–10, по умолчанию 4).
- **Бекап ClickHouse**: схема, данные таблиц в формате Native (gzip) и представления.
- **Пропущенные бекапы догоняются**: если в момент запуска по расписанию система была выключена или обновлялась, бекап запустится позже (пропуски не старше 6 часов).

### Улучшения
- Прогресс синхронизации хранилища виден по байтам, а не только по целым бекапам.

## v0.1.0 — 2026-10-14

Первый открытый релиз.

- Установка на сервер одной командой и обновление в один клик с откатом при ошибке.
- Бекапы серверов по SSH (каталоги, исключения, команда перед бекапом) и баз MySQL/PostgreSQL.
- Хранилища: диск SystemKeeper и S3, сохранение сразу в несколько мест, лимит числа копий и объёма.
- Проекты и группы проектов, история бекапов, скачивание файлов, описание бекапа для ручного восстановления.
