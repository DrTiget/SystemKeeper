# Что нового в SystemKeeper

Формат: раздел на версию, заголовок `## vX.Y.Z — ГГГГ-ММ-ДД`. Раздел версии попадает в описание релиза на GitHub
и в окно «Что нового» в приложении.

## v0.1.20 — 2026-10-24

### Безопасность
- **PHP 8.5.12.** Образ пересобран на PHP 8.5.12 — исправлены уязвимости PHP2Shell (CVE-2026-109618, CVE-2026-109619). Рекомендуется обновить установку.

## v0.1.19 — 2026-10-20

### Исправлено
- **Ложные алерты «Сервер не отвечает».** Внутренняя ошибка SSH-библиотеки (например, «Undefined array key 1») больше не считается недоступностью сервера: сбор метрик повторяется, а при повторном сбое данные просто устаревают. Трейс таких ошибок пишется в лог.

## v0.1.18 — 2026-10-19

### Новое
- **Приложения (интеграции).** Раздел «Приложения» (для администратора): у каждой интеграции свой статичный API-токен `ska_…`. Токен показывается один раз, а хранится только его хеш. Передаётся заголовком `Authorization: Bearer …` или `X-Api-Key`. Права выдаются по разделам на чтение и на изменение (`backups:read`, `servers:write`, `*:read` и т. п.). Токен можно перевыпустить или отозвать, приложение — выключить. Видны время и IP последнего запроса.
- **Публичный API.** По токену приложения доступно всё, что пользователь делает в интерфейсе: проекты, серверы, базы, бекапы, хранилища, мониторы, метрики, алерты, журнал. Закрыты только вход, профиль, пользователи, настройки, управление приложениями и обновление системы.
- **Документация API.** Страница «Документация API»: методы по разделам с параметрами, телами запросов и ответов, поиск и выгрузка OpenAPI-спецификации.
- **Журнал действий** (для администратора). Что пишется: изменения данных (было и стало), автор изменения (пользователь или приложение), IP и браузер. Также входы и выходы, бекапы, алерты, синхронизация хранилищ, выпуск и отзыв токенов. Пароли, ключи и токены маскируются. Фильтры по автору, событию, объекту и периоду. Старые записи удаляются автоматически, срок хранения по умолчанию 90 дней (настраивается).

## v0.1.17 — 2026-10-19

### Новое
- **Тестовое уведомление по правилу.** Кнопка «Отправить тест» в списке правил и в форме правила шлёт во все каналы правила пример уведомления именно этого правила: вид, важность, условие и реальный объект из его области (если объектов нет — «Пример объекта»). Алерт при этом не создаётся, правило не считается сработавшим. Результат показан по каждому каналу: «Telegram „Ops“ — отправлено» или «Почта — ошибка: …». Если в форме есть несохранённые изменения, они сначала сохраняются.

### Улучшения
- **Единый аккуратный вид уведомлений** для всех событий (сработало, напоминание, решено, тест). Письмо — HTML с цветной полосой по важности, крупным сообщением, таблицей деталей и кнопкой «Открыть в SystemKeeper», плюс текстовая версия; тема вида «[КРИТИЧНО] Сервер web-1: CPU 97%», «[РЕШЕНО] …», «[ТЕСТ] …». Telegram — жирный заголовок с эмодзи статуса (🔴 🟠 ✅ 🧪), строки «Объект / Проект / Правило / Начало / Длительность» и ссылка; названия объектов с `<`, `&` и подобным больше не ломают разметку. Вебхук получил поля `text` (простой текст) и `markdown`, прежние поля не изменились.
- Тестовые сообщения канала и тестовое письмо из «Настройки → Уведомления» оформлены так же.

## v0.1.16 — 2026-10-19

### Новое
- **Рекомендуемые правила алертов.** На странице «Алерты → Правила» SystemKeeper предлагает готовый базовый набор: сервер не отвечает, диск заполнен на 85% и на 95%, нехватка памяти, высокая загрузка CPU и нагрузка, недоступность сайта или порта, скорое истечение сертификата, неудачный и давно не выполнявшийся бекап, заполненное хранилище. Предлагается только то, для чего есть что отслеживать (серверы с метриками, мониторы, HTTPS-мониторы, бекапы по расписанию, хранилища с известным размером) и чего ещё нет среди правил. Достаточно отметить нужное, выбрать каналы и нажать «Добавить»; пороги потом можно поменять. Пока правил нет, набор занимает главный экран; позже блок можно скрыть, он вернётся ссылкой над списком.

## v0.1.15 — 2026-10-19

### Новое
- **Настройки → Уведомления** (для администратора). Почту теперь можно настроить из интерфейса: SMTP-сервер, порт, шифрование, логин и пароль, адрес и имя отправителя, с кнопкой «Отправить тестовое письмо»; раньше письма уходили через `MAIL_*` из `.env` и по умолчанию никуда не уходили. Если SMTP в настройках не задан, по-прежнему используется почта из `.env`. Пока почта не настроена, канал «Почта» создать нельзя — форма подскажет, где её настроить.
- **Telegram через прокси.** Адрес Bot API (по умолчанию `https://api.telegram.org`) и HTTP- или SOCKS5-прокси с логином и паролем: с серверов, откуда Telegram недоступен напрямую, уведомления теперь доходят. Кнопка «Проверить соединение» проверяет доступность адреса через прокси. Пароли хранятся зашифрованными и нигде не показываются, в текстах ошибок вырезаются.

## v0.1.14 — 2026-10-19

### Новое
- **Ресурсы серверов.** SystemKeeper снимает по SSH загрузку CPU, нагрузку (load average), память и swap, заполненность дисков, скорость сети, uptime и ОС — одним лёгким вызовом раз в минуту, без агента на сервере. На странице сервера — текущие показатели и графики за час, сутки, неделю и месяц; в списке «Серверы» — все серверы с мини-графиками. Статусы: данные свежие, устарели, не отвечает, сбор выключен. Для каждого сервера настраиваются интервал (30 с … 1 ч), срок хранения истории и исключённые диски. Во время обновления SystemKeeper сбор пропускается.
- **Алерты.** Правила на CPU, память, заполнение дисков, нагрузку и недоступность серверов, на падение сайта или порта и скорое истечение сертификата, на неудачный и давно не выполнявшийся бекап, на заполнение хранилища. Правило действует на все объекты проекта или на выбранные; условие должно продержаться заданное число минут, пока проблема не решена и не взята в работу — уведомление можно повторять, о решении сообщается отдельно. Каналы: Telegram, почта и вебхук (JSON с подписью `X-Signature`, HMAC-SHA256). У каждого канала есть тестовая отправка, ошибки отправки видны в канале и в алерте. Счётчик активных алертов — в меню, список и история — на странице «Алерты».

## v0.1.10 — 2026-10-19

### Новое
- **Мониторинг доступности (аптайм).** Мониторы HTTP(S) (код ответа, слово на странице, заголовки, редиректы, срок сертификата), TCP-порта, ping и DNS-записи. Проверки по расписанию каждую минуту выбирают подошедшие мониторы; недоступным монитор становится после заданного числа неудач подряд, при сбое открывается инцидент, при восстановлении закрывается. Uptime за 24 часа, 7 и 30 дней, среднее время ответа, разовая проверка без сохранения и проверка «сейчас». История проверок хранится 30 дней.

## v0.1.9 — 2026-10-15

### Новое
- **«Найти автоматически», что бекапить на сервере.** SystemKeeper осматривает сервер по SSH (только чтение): настройки (`/etc`, cron, свои скрипты), сайты и приложения (`/var/www`, `/srv`, `/opt`, `/home`, `/root`), корни сайтов из nginx и Apache, каталоги docker compose проектов, тома Docker, почту и сертификаты Let’s Encrypt — с размерами. Предлагает исключения (`node_modules`, кеши, журналы, файлы СУБД) и показывает работающие базы MySQL/MariaDB, PostgreSQL, ClickHouse, MongoDB и Redis — на сервере и в контейнерах, — отмечая, какие ещё не добавлены для бекапа дампом.

## v0.1.7 — 2026-10-15

### Новое
- **Страница «Последние бекапы»**: последний бекап каждого сервера и базы данных (нет бекапов — «НЕТ»), сгруппированные по группам проектов, проектам и серверам. Группы сворачиваются, состояние запоминается. Сверху — сколько всего, успешно, с ошибкой и без бекапов; у неудачных — ошибка и время последнего удачного.

## v0.1.6 — 2026-10-15

### Улучшения
- **Яндекс Диск: все файлы — по ссылке.** Раньше файлы меньше 8 МБ загружались напрямую — медленно (~0,3–0,5 МБ/с) и по одному, и бекап из множества мелких дампов шёл дольше многогигабайтного архива. Теперь Диск скачивает по ссылке всё, большие файлы — первыми.
- **Журнал синхронизации хранилища**: по каждому файлу — способ загрузки, размер, время и скорость. Те же строки — в журнале бекапа.

## v0.1.5 — 2026-10-15

### Новое
- **Бекап по ссылке-хуку.** У сервера и базы данных можно включить секретную ссылку: `POST` на неё запускает бекап — удобно вызывать из CI/CD перед деплоем. По ответу можно следить за ходом бекапа.
- **Что нового в приложении.** Нажмите на версию в меню — откроется история изменений по версиям; новые, ещё не установленные, отмечены.
- **Проверка обновлений вручную** — кнопкой в том же окне, не дожидаясь проверки раз в 10 минут.
- **Ход обновления по этапам**: ожидание бекапов, дамп базы, скачивание, перезапуск, проверка — с пояснением каждого шага; итог прошлого обновления (успех, ошибка, откат) виден в окне версии.

## v0.1.4 — 2026-10-15

### Новое
- **Яндекс Диск** как хранилище бекапов. Файлы от 8 МБ Диск скачивает сам по временной ссылке с SystemKeeper — это в разы быстрее загрузки напрямую. Число одновременных загрузок настраивается в подключении (1–10, по умолчанию 4).
- **Бекап ClickHouse**: схема, данные таблиц в формате Native (gzip) и представления.
- **Пропущенные бекапы догоняются**: если в момент запуска по расписанию система была выключена или обновлялась, бекап запустится позже (пропуски не старше 6 часов).

### Улучшения
- Прогресс синхронизации хранилища виден по байтам, а не только по целым бекапам.

## v0.1.0 — 2026-10-14

Первый открытый релиз.

- Установка на сервер одной командой и обновление в один клик с откатом при ошибке.
- Бекапы серверов по SSH (каталоги, исключения, команда перед бекапом) и баз MySQL/PostgreSQL.
- Хранилища: диск SystemKeeper и S3, сохранение сразу в несколько мест, лимит числа копий и объёма.
- Проекты и группы проектов, история бекапов, скачивание файлов, описание бекапа для ручного восстановления.
